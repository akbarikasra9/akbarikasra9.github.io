Assignment 6

Introduction

This page presents four interactive R Shiny applications developed for Assignment 6 in EPPS 6356: Data Visualization. The projects use built-in R datasets and external research data to demonstrate interactive filtering, reactive programming, data visualization, and web-based application deployment.

The applications were published using Posit Connect Cloud and GitHub Pages with Shinylive.

Part 2: Applications Using Built-In R Datasets

Application 1: USArrests Explorer

This Shiny application explores historical arrest statistics across the 50 U.S. states using the built-in USArrests dataset. Users can select an arrest category, adjust the minimum urban population percentage, and choose how many states to display. The interactive chart and table update automatically to reflect the selected filters.

Open USArrests Explorer in a new tab

Data source: R built-in USArrests dataset (1973).

Application 2: U.S. Population Explorer

This application visualizes historical United States population data using the built-in R uspop time-series dataset. Users can adjust the year range and visualization settings to explore how the U.S. population changed between 1790 and 1970. The accompanying table provides the population values associated with the selected visualization.

Open U.S. Population Explorer in a new tab

Data source: R built-in uspop dataset, historical U.S. population, 1790–1970.

Part 3: Optional Shinylive Extra Credit

Application 3: USArrests Explorer — Shinylive Version

This is a second deployment of the USArrests Explorer, published using Shinylive on GitHub Pages instead of a hosted Shiny server. Users can interact with the same historical arrest data and adjust the filters directly in their web browser. This version demonstrates how an R Shiny application can run client-side using WebAssembly.

Open Shinylive App in a new tab

Comparison of the Two Deployment Methods

The Posit Connect Cloud version executes the R Shiny application on a hosted server, whereas the Shinylive version runs the application directly in the user’s browser using WebAssembly. Shinylive eliminates the need for a separate R application server, but it may have greater restrictions on supported packages, performance, and browser compatibility.

Part 4: Original Data Application

Application 4: LLM Benchmark Explorer

The LLM Benchmark Explorer is an original interactive Shiny application that analyzes historical large language model evaluations from the Hugging Face Open LLM Leaderboard. Users can compare model families such as Llama, Qwen, Mistral, Gemma, Phi, DeepSeek, and Yi across different evaluation benchmarks, including instruction following, reasoning, mathematics, and knowledge-based questions. The application provides interactive filters, benchmark visualizations, a linked data table, and an option to download the selected results.

Open LLM Benchmark Explorer in a new tab

Data source: Hugging Face Open LLM Leaderboard v2, archived historical model evaluations (2024–2025).

Hugging Face Open LLM Leaderboard Dataset

Data note: The application uses a curated sample of historical model evaluation records. The benchmark scores should not be interpreted as comprehensive rankings of current language models or guarantees of real-world performance.

Conclusion

These four Shiny applications demonstrate the use of R for interactive data visualization and public-facing dashboards. The built-in dataset applications focus on historical demographic and arrest statistics, while the original LLM Benchmark Explorer extends these methods to published artificial intelligence research data.

Publishing the applications through Posit Connect Cloud and Shinylive also demonstrates two different approaches to deploying interactive Shiny applications on the web.

AI Disclaimer

AI Usage Disclaimer

I used generative AI tools, including ChatGPT, to assist with developing and troubleshooting the R Shiny applications for this assignment. AI assistance included generating and revising portions of R code, implementing interactive features, improving dashboard styling, resolving errors, and helping organize the Quarto webpage. I reviewed the generated code, tested the applications in RStudio, and made adjustments throughout the development process.

The applications use publicly available datasets, including R’s built-in datasets and historical evaluation results from the Hugging Face Open LLM Leaderboard. AI-generated responses were not used as substitutes for the datasets themselves. I also tested the deployed applications to evaluate their functionality and presentation.
